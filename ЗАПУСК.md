# HUSTLE: как запустить сайт с регистрацией и облаком

Состав папки:

| Файл | Зачем |
|---|---|
| `index.html` | сам сайт |
| `config.js` | сюда вписываются адрес и публичный ключ Supabase |
| `vendor/supabase.js` | библиотека Supabase (лежит у вас, из интернета не грузится) |
| `privacy.html` | черновик политики конфиденциальности |
| `_headers` | защитные заголовки для Cloudflare Pages и Netlify |
| `supabase/schema.sql` | таблицы и правила доступа |
| `supabase/seed.sql` | начальное наполнение: цены, ренталы, фестивали, статьи, курсы |
| `supabase/functions/` | три серверные функции: `ai`, `delete-account`, `update-rates` |

Пока в `config.js` поля пустые, сайт работает как раньше (демо в браузере). Облако включается, когда вы впишете ключи.

## Шаг 1. База и регистрация (Supabase)

1. Зарегистрируйтесь на supabase.com и создайте проект. Регион выберите осознанно: для данных казахстанцев проверьте у юриста требования к месту хранения.
2. SQL Editor → New query → вставьте весь `supabase/schema.sql` → Run.
3. Тем же способом выполните `supabase/seed.sql`.
3а. Для командной работы (приглашения по ссылке) выполните `supabase/team.sql`.
4. Authentication → Sign In / Providers → Email: включите подтверждение почты (Confirm email), минимальную длину пароля поставьте 8.
5. Authentication → URL Configuration: в Site URL впишите адрес сайта (пока временный адрес хостинга, потом домен) и добавьте его же в Redirect URLs.
6. **Почта.** Встроенная отправка писем Supabase рассчитана на тесты и ограничена. Для настоящих студентов подключите свой почтовый сервис: Authentication → SMTP Settings (подойдут Resend, Brevo, Mailgun и подобные).
7. Project Settings → API (или API Keys): скопируйте адрес проекта и **публичный** ключ (`sb_publishable_...` или `anon`). Впишите их в `config.js`. Секретный ключ (`secret` / `service_role`) в сайт вставлять нельзя.

## Шаг 2. Помощник ИИ и функции

Нужен Node.js. В папке с проектом выполните:

```
npx supabase login
npx supabase link --project-ref ВАШ_REF        # ref виден в адресе проекта
npx supabase secrets set ANTHROPIC_API_KEY=ваш_ключ_Claude
npx supabase secrets set CRON_SECRET=любая_длинная_случайная_строка
npx supabase functions deploy ai
npx supabase functions deploy delete-account
npx supabase functions deploy update-rates
```

Ключ Claude берётся в консоли Anthropic. Он хранится только в секретах Supabase.

Необязательные настройки (тем же `secrets set`): `AI_LIMIT_FREE` (запросов в день на бесплатном тарифе, по умолчанию 5), `AI_LIMIT_PRO` (на платном, 50), `ANTHROPIC_MODEL` (по умолчанию `claude-sonnet-5-5`; модель подешевле — `claude-haiku-5-5`), `ALLOWED_ORIGIN` (после покупки домена впишите `https://ваш-домен`).

**Курс валют по расписанию.** В панели Supabase откройте Integrations → Cron, создайте задачу раз в день, которая вызывает функцию `update-rates` и передаёт заголовок `x-cron-secret` со значением вашего `CRON_SECRET` (названия пунктов в панели могут отличаться). Пока задача не создана, курс остаётся прежним; пользователь всегда может ввести свой в меню профиля.

## Шаг 3. Выложить сайт

Подойдёт любой хостинг статики без GitHub:
- **Cloudflare Pages** → Create project → Direct Upload: перетащите всю папку (кроме `supabase/`, её можно не загружать).
- **Netlify** → Add new site → Deploy manually: перетащите папку.

Файл `_headers` при этом подхватится сам. Получите временный адрес, впишите его в Supabase (Шаг 1, пункт 5), проверьте регистрацию.

## Шаг 4. Когда купите домен

1. Привяжите его в настройках хостинга.
2. Добавьте домен в Supabase (Site URL и Redirect URLs).
3. Впишите домен в `ALLOWED_ORIGIN` функций и обновите секрет.
4. Добавьте в `<head>` файла `index.html` теги превью для мессенджеров: `og:url` и `og:image` (картинка 1200×630 по полному адресу).

## Как менять цены, фестивали и статьи без правки кода

В Supabase: Table Editor → таблица `content`. Строки `deals`, `rentals`, `events`, `articles`, `deal_urls`, `meta` — это данные в формате JSON. Меняете значение, сохраняете, сайт подхватит при следующем открытии. Если в `deals` вы удалите позицию, которая нужна готовым наборам или шаблонам сметы, новые цены не применятся и сайт останется на встроенных. Эти идентификаторы вынесены в проверку, это защита от поломки.

## Тариф

В таблице `profiles` у каждого пользователя есть поле `plan`. Значение `free` — бесплатно, любое другое (например, `pro`) — повышенный лимит помощника. Сейчас менять его можно вручную в Table Editor. Платёж и автоматическая смена тарифа **не сделаны**: нужен выбор платёжного сервиса и договор с ним.

## Что проверено, а что нет

Проверено автотестами с имитацией Supabase: вход, регистрация (с согласием), сброс пароля, отправка проекта в облако, загрузка после повторного входа, выход, сбой связи, подмена курса из базы, запуск без облака.

**Не проверено на настоящем Supabase**: мне отсюда недоступен ваш проект. Поэтому после настройки пройдите руками: регистрация → письмо → вход → правка проекта → выход и вход с другого устройства → вопрос помощнику → удаление тестового аккаунта. Функция `update-rates` написана по описанию формата Нацбанка и не запускалась с реальными данными: проверьте её вызовом вручную.

## Что осталось сделать

- Заполнить `privacy.html` и показать юристу.
- Платёжный сервис и автоматические тарифы.
- Рисунки раскадровки лежат внутри проекта; когда их станет много, проект перестанет помещаться в облако (лимит около 6 МБ). Следующий шаг: Supabase Storage.
- Фон главной небольшой (736×414): для чёткости замените на фото от 1920 px (кнопка «Заменить фото в шапке» подходит для одного устройства; встроенный фон меняется в коде).
- В CSS остались неиспользуемые стили от старых версий: они не мешают, но чистить их удобнее в исходниках (`hustle-src.zip`), а не в склеенном файле.
